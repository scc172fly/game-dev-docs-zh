结算细节与源码

字段配置

两种资源上下文都读取心灵乐章标记 A4_2_Active。被动强化自身及全局未登记 A4_2_Power，独立预览按 0 回退；实际施放的基础旋律登记了 50%，标记为 1 时乘 1.5。 缺失回退 · 基础旋律常量
返能时读取当刻的 A4_2_Active，并取计数器上次枚举的护盾数，最多计两个。相关属性为 50、计数为 2 时，常态返 72，乐章生效返 108。 运行依据

状态变化 先用 UNIT 取自己的首个同名计数器。它在模拟步中重新枚举自己发出的两种护盾效果的接收者，读取的是上次枚举所得的 targetsCount。别人挂在同一目标上的盾不会增加这项返能。常态下计数 2、1、0 分别返还 72、36、0。 状态源码

冲突结算 同一施法者重挂同一种防护旋律护盾会停止旧盾，新盾结束后旧盾不会回来。不同施法者挂同一种盾时才进入跨来源冲突分支；比较优先级及剩余时长，吸收量不参与这项比较。 冲突源码

同帧读取 常态、相关属性 50，计数器上次枚举到一个盾。旧盾消失后，返能先触发仍读到 1 个盾，返 36；计数器先更新则读到 0，返 0。重挂盾后，同一个计数器要再次枚举才会把新盾计入。 时序源码

跨单位更新 队友身上的盾在队友更新时到期，计数器在吟游诗人身上重新枚举。队友先移除最后一个盾，诗人再枚举，之后的常态返能为 0；若诗人先枚举到一个盾，即使队友随后移除了它，再次枚举前仍可返 36（相关属性 50）。 更新顺序源码

死亡与退召 盾目标死亡时，返能先读计数器上次枚举的结果。上次只有一面盾时仍对应 36；目标清理及后续重新枚举得到 0 后，才按 0 计算。 死亡清理源码

复活与重召 复活后返能仍取计数器最近一次枚举值。重新枚举时没有自己的盾则为 0，重新挂上一面并被枚举后为 36。 复活源码

复活当帧 复活通知不重新枚举护盾。同步返能读取上次枚举值；若上次为 0 且本步仍未枚举到自己的盾，英雄更新后的读取也为 0。 投递结算源码

投递等待与取消 返能实际执行时读计数器上次枚举的盾数。若等待期间该值由 2 更新为 1，恢复接收后执行一次返 36；若该投递被取消，本次没有返能。 投递重试源码

逐项拦截 返能在 A3 投递最后一个程序内。只拦前面的独立治疗，程序仍可启动；满足返能条件且计数为 1 时返 36。拦截整个程序则无法执行里面的返能，先前已生效的治疗保留。 逐项应用源码

嵌套程序 A3 的返能程序先等候，再建立护盾计数器，最后执行返能。拦外层程序不会返能；只拦计数器，最后一步仍尝试查找。没有旧同名计数器时按 0 返能，新计数器枚举到一面盾时返 36。只拦返能步骤则不发放。 程序推进源码

等待子效果通知 A3 首步是空效果，按 cA3_Duration − cSTEP 延时。计时恰好到 0 仍等，降到负值才开始枚举护盾；当前计数器启动后发出 START，程序可在这次推进内进入返能。若有效盾在枚举前由两面降为一面，返 36；枚举时仍有两面则返 72。 通知处理源码

延时与通知同帧 A3 的延时首项没有子效果，因此没有能给这一步放行的子效果 STOP 或 DONE。延时归零时还不枚举，扣到负值才枚举一次；之后计数器的 START 可放行返能步骤。枚举时剩两面盾返 72，剩一面返 36，不会重复返能。 延时推进源码
